Scope: diff `ad484ad~1..HEAD` (src, bot, test, e2e): BAL-R6 (core numbers, power attribute, bot, new tests, golden), UI-R6, WORLD-R6. Read-only. `npm test`: 686/686 pass (33 s).
Verdict: **changes needed** (no blocker; 8 should, 7 nit). The golden re-record is justified. The power-attribute formula is correct and deterministic.

## Checked and fine (evidence)
- Golden re-record. Experiment in the scratchpad: HEAD tree with the five core data files (`config.js`, `classes.js`, three `skilltrees/*.js`) and the fixtures put back to the pre-R6 versions, `derive.js` kept at HEAD: `determinism.test.js` and `class-determinism.test.js` pass with the OLD hashes (8/8). So the formula change is neutral by default (`powerAttr ?? "grit"`) and the new hashes come only from the data changes listed in R6-balance.md section 2. `git diff --stat` shows `src/core` touched only in config, classes, three skill-tree files and derive.js. Nothing unintended is hidden. Limit: I did not attribute the hash change number by number, and the 500+ tick replay probably exercises few tree-skill numbers (only the formula, hp, xp and monster scaling are certain), so the golden says little about the skill-number tuning.
- Formula (`src/core/items/derive.js:48`): `attrs` already includes gear, `Math.max(0, ...)` guards negative gear, floor is applied once at the end. Float check: floor(n*0.8), floor(n*0.6), floor(n*0.5) equal exact integer arithmetic for n 0..1000. Pure function of state, no RNG, no wall clock: determinism holds and the golden covers it (class hashes differ per class, tested).
- Save import cannot set `powerAttr`: it comes from `classById(player.class)` and `d.class` is validated against content (`src/save/format.js:148`). The exploit surface is the attributes themselves, see CR6-02.
- lowFx: lazy atlas is independent of it; `tint`/`restore` paths are skipped under `env.lowFx` (world.js:258, 288, 392), `redrawHero` only tints when `tintA > 0`. OK.
- Atlas memory: silhouette cache keys are the finite pool/status colours, entries are built only for sprites actually shown. Lazy makes memory smaller, not larger.
- R6 hot-path allocations: `fx.onHead`, the beam/hero overlap test, `redrawHero`, `monFrame` allocate nothing per frame. The fps50 swing 46.2 / 38.5 is not explained by a new allocation in the diff (see CR6-12 for the one small candidate).
- Esc handling of the respec confirmation: the `doc` capture listener runs before the `window` bubble listener in main.js:205, so Esc closes the confirmation first. Focus goes to the safe button ("Cancel", `rs.no`) and returns to "Respec" on close. Good.

## Findings

### CR6-01 [should] Employee File still says "Grit raises damage" for every class
`src/ui/panels.js:21`, `src/ui/text.js:33`, shown at panels.js:114. For the Sales Rep (power attribute Agility) and the IT Wizard (Focus), Grit now does nothing for damage, while the attribute hint on Agility says "raises defense and aim" and on Focus "raises mana". A player following the hints spends points on the wrong attribute; there is no attribute respec, so it is permanent. Package boundary gap: BAL-R6 changed the meaning, UI-R6 was not told.
Fix: derive the hint from the class: `derivedFor(class).powerAttr` shows "raises damage (and ...)" on that attribute, plain hint elsewhere. Add a ui test per class.

### CR6-02 [should] A save can carry any attribute values up to 1000, now for every class
`src/save/format.js:152` validates `attrs` as 0..1000 each and `attrPoints` 0..1000 independently; there is no invariant like the skill-point one at :171 (`spent + skillPoints <= (level-1)*perLevel`). Level 1 with `grit` or the class's power attribute 1000 gives about +990 damage per hit (no damage cap in `config.caps`), stamina 1000 gives 3000 hp. This existed for grit before R6; R6 makes it true for Agility and Focus too (all three classes) and the checksum is not a secret. Single player, so the impact is self-cheating, but the file also advertises a point invariant elsewhere.
Fix: compute `classSum = sum(cls.attrs)` and require `sum(attrs) - classSum + attrPoints <= (level-1) * config.attrPointsPerLevel`, and each attribute `>= cls.attrs[a]`. Check no gameplay source grants free attribute points (grep shows only `progression.js:22` and `cheats.js:18`). Add to the save fuzz/validation tests.

### CR6-03 [should] `lazyDraw` re-applies the ink/texture globals but never restores them: an atlas rebuild in flight is corrupted
`src/render/styles/vector/index.js:59-62`, `src/main.js:94-96`. During a rebuild (zoom/dpr/high-contrast change) the OLD atlas stays in use while the new `build()` runs its steps across `await yieldFrame()`. Any lazy sprite first shown in that window now calls `setInkScale(oldZoom); setTexRes(oldScale)` and leaves them set; the new build's remaining eager steps (props, decor, fx, UI icons) then draw with the old atlas's ink weight and resolution, permanently baked. Before R6 the lazy draws used the new globals (the reason for `lazyDraw`); the fix moved the hazard. The R6 claim "a later rebuild cannot change them" is true for lazy sprites only.
Fix: in `lazyDraw` save the current values and restore them in `finally` (needs getters from `ink`), or re-apply both globals at the start of every `steps[i]()` in `build`. Test: build A, start B (stub yields), get() a lazy sprite of A between B's steps, assert B's eager sprite saw B's values.

### CR6-04 [should] Nothing warms the lazy monster/hero frames: first sight of a type is drawn inside a frame
`src/render/world.js:53` (`warmHero`) has no caller (grep of src, test, e2e, bench, bot: only the definition), though its comment says the shell spreads it over class selection. R6 moved all 8 monster types and the S1 hero to `addLazy` (4.8 s to 0.5 s build) so each new (type, anim, direction, frame) now costs a rim bake (about 4 ms from the build numbers) inside the draw loop; a pack of six awake monsters in different facings on entering a floor can be 20+ ms in one frame, and walk cycles keep adding single hitches for the first minutes. lowFx does not help, this is first-use cost.
Fix: wire a budgeted warm (idle and walk, facing the camera and the 3 most common directions) for the floor's monster types on floor generation, using the loading overlay or `requestIdleCallback` with `budgetMs`, and call `warmHero` on class select / continue. Report `__atlasStats.lazyMs` per run in the bench (PERF-R6 owns the number).

### CR6-05 [should] The no-xp watchdog can hide a real chase/AI defect, and its counter is mixed with the old wait counter
`bot/policy.js:318-320`. The documented trigger (IT seed 11 sat at level 3 for 41 min) is "an awake monster that never arrives": that is either a core chase/pathing bug or a legitimate blocked case; the fix writes every awake monster off after 60 s without xp and reports it through `mem.waitGaveUp`, the same counter as the 240-tick wait give-up, so the parity and bot reports cannot tell the two apart. `balance-gate.test.js` asserts `stuck == 0` but nothing about the watchdog. It also fires in the Lobby (depth 0 is `< bossDepth`) and while a human-like long walk to the stairs has no xp (harmless there, but noisy).
Fix: separate counter `watchdogFired` in memory, `summarise` and `parity.mjs`; assert it is 0 in `balance-gate` (or at most N with a comment); open a core ticket to root-cause why a chasing monster never reaches the hero on that seed (record the seed and tick), and skip the watchdog at depth 0.

### CR6-06 [should] `skill-cast.test.js` proves "a cast happened", not "the skill works"
`test/skill-cast.test.js:20-28, 38`. The area check is any `burst` event (passes with zero damage), the self/buff check is `buffs.length > 0 || heal event`, the dash check `player.dash`. No assertion that the monster 5 tiles away loses hp for damage skills, that a heal heals, or that the shield absorbs. The F5 follow-up (Power Surge / Packet Filter) is covered by the two dedicated tests, which are fine (mana, absorb pool, hit event), but the loop over 20+ skills would still pass if an effect list were emptied.
Fix: for `damage` effects place the monster in range and assert `monster.hp` drops (or a `hit` event with `skill === def.id` after `run(st, 120)`); for heals assert `hp` rises from a wounded start.

### CR6-07 [should] A refused cast gives the player no feedback (the R5 "mana unchanged" report is closed as "spec-conform")
`src/core/systems/skillfx.js:120-135` refuses with "no direction" / "needs a target tile", `intent.js:139-144` returns it, and no UI mapping exists (grep of `src/ui`, `src/game.js` for those strings finds nothing). The balance note explains the observation but the player still sees nothing when right-clicking their own tile. Not a core bug; a UX gap that will be reported again.
Fix: toast or a shake on the target cursor for `castSkill` failures other than `noMana` (that one already has an event), short text per reason.

### CR6-08 [should] Respec dialog and tree: accessibility gaps
`src/ui/tree.js:76-82`, `:36-45`, `src/style.css` (`.tree .tl`, `.tn-req`).
- The dialog is `role="alertdialog"` but has no `aria-modal`, no `aria-describedby` for the refund text, and no focus trap: Tab leaves it into the tree behind it while it is open. Focus moves in correctly and Esc works.
- Tier labels are `aria-hidden` and the node `aria-label` (line 39) does not include the tier, so screen-reader users get no tier or prerequisite information except through `lockReason`; the "Needs: ..." text is `display:none` on desktop (`.tree .tn-req`) and the visible lock reason was dropped from the card (`lock` at tree.js:36 is now an unused variable). Keyboard and mouse users on desktop lose "Needs Level 8" on the card too; it survives only in the tooltip.
- Connector colour (green vs purple) is the only visible prerequisite-met signal; the state word covers it for the node itself, so this is fine, but add the prerequisite names to the `aria-label` (`n.requires` is in scope).
Fix: add `aria-modal="true"` plus `aria-describedby="rs-text"` (id on the refund paragraph) and trap Tab between the two buttons (or make the rest of the panel `inert` while `respecAsk`); put tier and prerequisites into the node label; restore the lock reason as visible text on desktop (it fit before) or show `tn-req` at desktop with the unmet requirement only.

### CR6-09 [nit] `justify-content: safe center` has no fallback
`src/style.css` `.screen.pause`. On a browser without `safe` the whole declaration is dropped and the earlier centring returns: the overflow-off-the-top bug (N6) comes back. Robust form: `.screen.pause { justify-content: flex-start } .screen.pause > :first-child { margin-top: auto } .screen.pause > :last-child { margin-bottom: auto }` (auto margins centre only when there is room). Same remark for `:has()` in the phone rules (`#ui.phone .tree .tnode:not(:has(...))`, Firefox before 121): degrades to a half-width Learn button, acceptable.

### CR6-10 [nit] `.sl-foot` layout couples to magic numbers
`src/style.css` `.sl-foot`: `bottom: -16px` and `margin: 0 -16px -16px` assume the card's 16 px padding (12 px at 520), a hard-coded `#241d4e` background and `#3d3068` border instead of tokens, and no `html.hc` rule. A padding change in `.sl-card`/dialog silently breaks the sticky row. Use a CSS custom property for the padding, and tokens for colours.

### CR6-11 [nit] Balance gate tuned to what it tests; parity not enforced
`test/balance-gate.test.js`: deterministic (seeded, tick-bounded, 11 s), so not flaky, and the margins today are comfortable (level 7 vs required 6; floor 4 at 28 000-34 000 of 45 000 ticks). But (a) it uses seeds 1-3, a subset of the 24 tuning seeds, and the careful bot the numbers were tuned for; (b) it stops at floor 4, so the boss-fight parity (where the caster loses 27 of 63 deaths) and the 20-40 min band are not gated at all; they only live in `node bot/parity.mjs` by hand; (c) any later change that shifts clear time by more than about 30 % fails with a message that does not say which knob moved. R6-balance.md is honest that IT is one death outside the band on the median and the FM missed 1 of 24 runs (seed 20, 8 boss deaths): both stay open, name an owner.
Fix: add a nightly/release job that runs `parity.mjs 24` and fails on the band verdict, using mean deaths as the doc proposes; add a different seed range (e.g. 101-103) to the gate to catch tuning to seeds.

### CR6-12 [nit] Silhouette lookup allocates a string per call in the hot path
`src/render/atlas.js:9`, `const cache = ..., ck = mode + colour;` runs on every `atlas.shade/tint/flash` call, up to 3-5 times per lit actor per frame; R6 adds ghost actors to the restore list (world.js:~368 now `it.a > 0.6`, including ghosts) and the hero redraw, so there are more calls per frame. V8 concatenation produces a cons-string each time (short-lived garbage), small but this is exactly the allocation class the quiet bench is sensitive to.
Fix: two-level cache (`cache[mode]?.[colour]`) or intern the key once on the item (`it.tintKey`). Measure before/after with the PERF-R6 bench; do not expect the whole 46 to 38 swing from it.

### CR6-13 [nit] `redrawHero` ignores depth order against actors in front of the hero
`src/render/world.js:~346`, `fx.js:~697`. When a loot beam overlaps the hero's rect the hero is blitted over the whole frame so far, including monsters or props that stand in front of him (and the hurt wash twice). It looks right for the beam case the shots show, wrong when a monster overlaps the hero's lower body in the same frame. Mitigation: only redraw when no actor item with larger `d` overlaps the hero's rectangle, or clip to the beam's x-span. The N3 test stubs `heroRedraw` and never calls `redrawHero` itself.

### CR6-14 [nit] Test quality in the new render/UI tests
`test/render-r6.test.js`: the N1 face test counts `ellipse` calls with magic eye radii (2.5/3.5, 3.7) so any art tweak fails it, and the test titled "pale actors are one step darker (Consultant and Middle Manager skin, Consultant rim)" asserts only the rim luminance. The perf test covers `addLazy`, not `lazyDraw` or `monFrame` (the places with the bugs in CR6-03). `test/ui-r6.test.js`: layout is protected by regexes on the CSS source (change detectors, they pass while the layout is broken and fail on harmless reformatting); there is no test for Esc/focus of the respec dialog (only the e2e `adv-r5.mjs:491` clicks through it, and it now does click `respec-yes`).
Fix: assert behaviour (a skin-luminance check, a frame-table test that `monFrame` draws once), keep one real-browser layout check at 720 in e2e.

### CR6-15 [nit] Old saves and gear: no note, no validation of `powerAttr`
- Pre-R6 saves keep their attribute spending: an IT Wizard or Sales Rep that followed the old hint put points into Grit and cannot take them back (respec covers skills only); the xp curve change (`quad` 36 to 26) also shifts level thresholds under existing xp. No `saveVersion` bump or release note. Acceptable for a prototype, but say so in the release notes, or offer an attribute respec in the same Lobby action.
- `derived.powerAttr` is trusted: a typo gives `attrs[undefined]` = NaN damage (`Math.max(0, NaN)` is NaN). Add a content test: `powerAttr` in `["grit","agility","stamina","focus"]` for every class and the config default.
- Gear requirements are grit-based (`items.js`, e.g. Stapler Mace needs Grit 12) while casters and the ranged class no longer scale on Grit; affix pools were not touched (noted in R6-balance.md section 9). Fine now, track for R7 (gear-driven visuals).
