# 13 Gear visuals

Areas: F (items), G (UI), NFR-A03, NFR-P01, NFR-P02, NFR-Q01. Date: 2026-10-15. Author: architect (with the spec-writer's AC rules). Status: draft. Round: R8-0. Inputs: `../00-brief.md` (seventh briefing, real customer: "the characters change their visuals based on the inventory"; interpreted as the **equipped** visible slots), `../decisions/ADR-0008-gear-visuals.md`, `05-items-and-loot.md`, `11-classes-trees-slots.md`.

## Conventions
- New requirements (to be added to `../20-requirements.md`): **R-260** (must) the hero's figure shows the equipped gear in the visible slots; **R-261** (must) rarity reads through trim and shape, uniques have one distinct accent; **R-262** (must) no cost to determinism, load time or frame rate.
- Level: `Unit` (Node, canvas stub or `OffscreenCanvas` polyfill used by `render-*.test.js`) or `E2E` (Playwright, `?test=1`, `window.__app`). "Visible slots" = head, body, hands, feet, weapon, offhand. Hook names are proposals: `__app.perf()` gains `gearCache` (`{frames, bytes, builds, evictions, fallbacks}`) and `gearSig`; `render/gearlooks.js` exports `gearSignature`, `LOOK_BY_BASE`, `LOOK_CATEGORIES`.
- Anything judged by eye is marked `verify: playtest/visual review`.

## Acceptance criteria (14)

### R-260 The figure shows the equipped gear (must)
- **AC-R-260-1** `R8` `Unit` — Given `content.bases` of kind gear with a visible slot, When `LOOK_BY_BASE` is checked, Then every such base maps to a category of `LOOK_CATEGORIES[slot]` (21 categories, at most 5 for the weapon slot, 3 offhand, 3 head, 4 body, 3 hands, 3 feet), no other base appears in the table, and `gearSignature` returns the same string for any two items with the same categories and rarities in the six visible slots and ignores belt, rings and amulet.
- **AC-R-260-2** `R8` `Unit` — Given each of the 3 classes, 8 facings and the anims idle, walk, attack, cast and death (frame 0 and the last frame), When a frame is built with one item equipped in one visible slot at a time (21 categories, tier normal), Then it renders without error, differs in pixels from the same frame with the slot empty, and differs from the frame of every other category of that slot (so the 21 categories are visually distinct in every class and facing).
- **AC-R-260-3** `R8` `Unit` — Given a hero with all six visible slots empty, When a frame of any class, anim, facing is built through the gear path, Then its pixels equal the pre-R8 atlas sprite of that key (the empty look is unchanged, class prop kept); and with a belt, ring or amulet equipped and the six slots empty the pixels are still equal.
- **AC-R-260-4** `R8` `E2E` — Given a running game, When the player equips, swaps and unequips a visible-slot item through the Desk Drawer (click or drag), Then within 2 s the hero's canvas pixels in the hero rectangle change (equip), change again (swap to another category), and return to the pixels of the empty look (unequip), `perf().gearSig` follows, the frame loop shows no error, and carrying an unworn item changes nothing.
- **AC-R-260-5** `R8` `Unit` — Given an item whose base is unknown to `LOOK_BY_BASE` (or whose rarity is unknown), or a null, malformed or invisible-slot item, When the signature and the frame are built, Then no exception escapes, the slot is drawn with the slot's plain default category (unknown base, visible slot) or not at all (malformed, invisible), `perf().gearCache.fallbacks` counts a throwing painter, and a throwing painter leaves that slot empty while the rest of the figure is drawn.
- **AC-R-260-6** `R8` `E2E` — Given the Employee File, the slot cards of the character slot list, and the character select, When a character with gear in the visible slots is shown (Employee File open; slot index with a stored `look`; class card for a new character with the starting kit worn), Then each busts canvas differs from the bare bust of the same class, an index entry without `look` shows the bare bust, a malformed `look` is ignored (bare bust, no error), and equipping in game repaints the Employee File bust within one panel refresh.

### R-261 Rarity and uniques (must)
- **AC-R-261-1** `R8` `Unit` — Given one category per slot at tiers normal, magic, rare, unique, When the four frames are compared, Then all four differ pairwise in pixels inside the part's bounding box, the difference between any two tiers includes a shape change (stud, double edge or accent mark) and not only a hue change (the grey-scale versions of the four also differ pairwise), the trim colours are the Okabe-Ito entries of `palette.js` (sky blue, yellow, vermillion), and all uniques share the one unique accent (a unique of base A and a unique of base B in the same category give identical part pixels).
- **AC-R-261-2** `R8` `Unit` — Given the four rarity colours of the trim, When they are put through the deuteranopia, protanopia and tritanopia simulations of `test/palette.test.js`, Then every pair keeps the minimum distance that test already requires for the item rarity colours.
- **AC-R-261-3** `R8` `E2E` — Given 1x screenshots of each class with the six slots at tier normal and at tier unique, and with a rare set, When a reviewer looks at the crops (`docs/shots/r8-gear-*`, one per slot and class), Then the equipped slot is identifiable at 1x and the rarity reads without the item label. `verify: playtest/visual review`.

### R-262 Determinism, load, frame rate (must)
- **AC-R-262-1** `R8` `Unit` — Given `run-a.json`, `run-class.json` and the three class goldens, When they are replayed with the render path active (gear signature computed, cache built from a stubbed renderer each tick) and with it off, Then the final state hashes are equal and equal to the pre-R8 goldens; no file under `src/core` or the save format changes, and `gearlooks.js` and the part painters contain no `Math.random`, `Date.now` or core RNG call (static scan).
- **AC-R-262-2** `R8` `Unit` — Given the same class, signature, anim, facing and frame, When the frame is built twice (also after the cache evicted it), Then the pixels are identical; and the same signature in the UI figure (`drawFigure` with `look`) and in the game cache give the same figure at the same size (within the scale, compared at 1x).
- **AC-R-262-3** `R8` `E2E` — Given a cold load, When `perf().atlasMs` is read, Then it is below 5000 ms and no gear sprite is in the eager build (`perf().gearCache.builds === 0` before the first frame of a game); and the gear cache never exceeds 32 MB (`perf().gearCache.bytes`) during a run that equips 40 different random item combinations in sequence, with no per-frame canvas allocation (`builds` grows only on a signature change).
- **AC-R-262-4** `R8` `E2E` — Given the bench with 50 monsters on screen and the hero fully geared (six slots, unique tier), When `fps50` is measured 5 times and the floor load section runs (floors 2 and 5, ahead and cold), Then the fps50 median is >= 48 on the CI reference runner (or not more than 1 fps below the same-session pre-R8 median elsewhere), frame p99 after a floor load is <= 33 ms, in-window lazy draws are 0, and changing the signature costs at most one lazy draw plus 0.7 ms of warm work in any frame (`perf().gearCache.maxBuildsPerFrame <= 1`).
- **AC-R-262-5** `R8` `Unit` — Given a floor change, a game load, a respawn after death and a class change, When the equipment references change or not, Then the cache is reused when the signature is unchanged (no builds), switched atomically when it changes, never mixed between classes, dropped with the atlas on rebuild, and no gear warm work runs in the 240 frames after a floor change (counter in `warmState`).
