### Results after retro R5/G (2026-10-14; evidence for `harness-reviewer`, who decides at the post-mortem)

| # | Status | Numbers and evidence |
|---|---|---|
| E1 | **Supported on defect yield, refuted on the reviewer-blocking threshold, order untested.** | Adversarial pass (R5, first ever): round 1 = 11 findings (0 blocker, 4 major, 7 minor), round 2 on the fixes = 12 verified fixed + 3 new minor, total 14 (expected: >= 1 per round, met). 8 of the 11 round-1 findings were not in the code review (3 overlapped: ADV-02 = CR-01, ADV-09 ~ CR-09, ADV-04 ~ CR-03). Code review found 2 blocking (CR-01 stale lock, CR-02 stored XSS via imported item id), 13 should, 13 nit; expected "reviewer blocking <= 1" was not met (2), and CR-02 was found by the review only. The pass did not run before the review (both started after UI-R5, review done in 6.1 min, adversarial 41.7 min), so the hypothesis' ordering ("before the reviewer lowers the reviewer's blocking count") is untested. Cost: adversarial 463.0 k tokens / 109.5 min wall clock for 14 findings (33 k per finding) vs review 241.5 k / 6.1 min for 28 (8.6 k per finding; 16 k per non-nit). Side effect: 59 test cases + 12 XFAIL e2e checks became regression tests (suite 574 -> 668). Reading: the two passes are complementary (L-030), not substitutes; keep both. Sources: R5-adversarial.md, R4-R5-G-code-review.md, ledger.jsonl, round-05.json. |
