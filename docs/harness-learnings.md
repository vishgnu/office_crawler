# Harness learnings from Office Crawler

Each entry: what happened, what it says about the harness, what was changed (file + commit) or proposed.

| # | Date | Observation | Harness change |
|---|---|---|---|
| L-01 | 2026-10-13 | The first non-web-app target (static browser game) has no stack pack; `node-postgres` assumes a server and DB | Added `harness/stack-packs/static-web/` (single-file build, seeded RNG, test hook, Playwright smoke, SWA preview workflow) |
| L-02 | 2026-10-13 | The user wants an agent to stand in for them; the facilitator's rule "never answer on the user's behalf" had no sanctioned exception | Added `customer-proxy` agent with a delegation record, PROXY tags and an escalation list |
| L-03 | 2026-10-13 | The spec-writer produced 341 acceptance criteria for a game MVP (S1 104 / S2 165 / S3 72). Every AC is automatable, but the volume slows review and implementation, and many ACs assert UI details nobody asked about | **Applied** to `harness/.claude/agents/spec-writer.md` |
| L-04 | 2026-10-13 | The facilitator's spec questions arrive after circles end; with a proxy they can be answered at once, but there is no file convention for post-circle questions | **Applied** to `harness/07-requirements-circles.md` |
| L-05 | 2026-10-13 | The architect and the customer-proxy ran in parallel and both decided the same open spec questions (e.g. skill keys: QWER vs F1–F4 + right mouse; boss on floor 8 vs a separate arena) | Rule: open questions have ONE owner. Customer-facing/UX/scope questions go to the customer (or proxy). The architect only lists them and may decide technical ones. When they conflict, the customer answer wins. **Applied** to `harness/04-agents.md` and `architect.md` |
| L-06 | 2026-10-13 | A unit test with a 50 ms wall-clock threshold failed 1 run in ~12 under parallel load. The orchestrator caught it only by re-running | Rule added to `test-engineer.md` and `implementer.md`: no tight wall-clock assertions in unit tests; bound work (node/iteration counts) instead; performance goes to a separate benchmark. Run the suite ≥3× before handing back |
| L-07 | 2026-10-13 | The reviewer found 4 more wall-clock thresholds after L-06. Cause: the rule was added while the S1-4 implementer was already running, so rule changes don't reach agents already in flight. A second cause: the existing tests were never re-checked against the new rule | The orchestrator re-checks the codebase against every newly added rule (grep or a lint) right after adding it. Rules that can be machine-checked should become a test/lint, not only prose. Proposed: a lint test in the static-web pack that flags `performance.now()` inside `assert` in `test/` |
| L-08 | 2026-10-13 | The independent code review found a real blocking input bug (mouse-up while paused) that 96 unit tests + 89 e2e checks missed: all checks were written by the same agent that wrote the code | Keep the reviewer independent of the implementer. Have the test-engineer (not the implementer) write adversarial e2e sequences (pause/resume/blur/resize during input) |
| L-09 | 2026-10-13 | The portal showed no readiness for the game: the facilitator wrote the score as a table row (`Total | **9**`) instead of `N of 20`. Free-form agent output breaks tooling that reads it | **Applied**: `requirements-facilitator.md` now requires `Status:` and `Readiness: N/20` lines; the portal parser accepts the canonical line plus older forms (tests added); `--status` option lets a project use its own status file |
| L-07b | 2026-10-13 | Follow-up to L-07 | **Applied**: `static-web/skeleton/test/lint-rules.test.js` checks no wall-clock timing in tests and no `Math.random`/`Date.now` in `src/core` |
| L-10 | 2026-10-13 | Running several implementers in parallel worked once each had an explicit list of files it may edit, and cross-agent needs went through notes files (`S2-world-notes.md`, `S2-ui-notes.md`) instead of edits in someone else's files. Without that, the S1 polish and S2 core agents left the suite red mid-run, and that red state landed in WIP commits | **Applied** to `harness/04-agents.md` ("Parallel work packages"). A red suite in a WIP commit is acceptable only if the commit message names the agent that owns the fix |
| L-11 | 2026-10-13 | Core-first, then render/UI: the pure core plus tests let the bot play 8 floors before a single sprite existed, so balance and pathing bugs (orbiting, corridor rings) were found early and cheaply. The cost: the renderer must catch up to a long `render_needs` list | Keep it. Ask the core implementer to return `render_needs` as a structured list (it did, unprompted) and make it a required field of the implementer's result |
